# Issue #6 — MiMo Desktop 原生产物预览验证记录

> 状态：**已得出 No-Go 结论**（见「实验结果」）。本文件归档验证过程与判据，便于后续版本复核。
> 范围：仅原生 `present_files` 与受控文件路径；明确禁止修改 `app.asar`、注入桌面 UI。

## 先决条件

- 使用能够正常执行 `/usage` 和 `/usage-open` 的 MiMo Desktop 版本；
- 准备独立的无敏感信息 HTML，如 `<html><body><h1>preview probe</h1></body></html>`；
- 在实验前确认当前会话工作目录与应用侧边栏产物区；
- 不使用真实用量数据库、令牌或带隐私路径的文档作为实验素材。

## 验证矩阵

| 编号 | 操作 | 必须记录 |
|---|---|---|
| P1 | 在会话调用原生 present_files 登记测试 HTML（用户数据目录） | 工具是否可用、调用参数、错误、是否有卡片 |
| P2 | 点击卡片 | 是否可在 Desktop 内预览实际 HTML（不是纯文本/下载） |
| P3 | 如 P1 失败，尝试当前会话目录下相同文件 | 路径限制、是否污染工作树 |
| P4 | 重复登记同一路径文件两次 | 是否产生冗余版本、额外 git 操作或 AI 标记 |
| P5 | 禁止/拒绝 present_files | HTML 仍可由路径打开，原有 CLI 不受影响 |
| P6 | 检查实时页面 `127.0.0.1` | 内嵌预览是否允许动态连接；不可把静态截图当实时能力 |

## Go / No-Go

**Go**：至少静态 HTML 能原生预览，受控调用不会带来不可接受的 AI 标记、Git 写入、额外消耗或隐私暴露。

**No-Go**：工具不能被应用调用、仅下载/纯文本而不能预览、或副作用无法接受。停止集成，文档说明该应用版本不支持。不得转向 `app.asar` patch。

## 通过后才允许的实现

1. 优先仅调整 `register_command.py` 中 `/usage` 模板：Python 脚本生成数据，agent 仅登记已有文件，绝不改写统计和 HTML。
2. 若有路径限制，优先复用 `usage_cli.py --out`，不变更默认持久化目录；临时文件必须位于受控目录。
3. `/usage-open` 原有浏览器和 loopback 行为保持原样。
4. 测试包含未安装原生工具的回退、重复调用和安装器配置保留行为。
5. 更新 `README.md`、`README.en.md`、`docs/plugin-interface.md`；以实测结论为准。

## 实验结果（2026-10-16）

### P1 — **已实测：工具可用，能登记 HTML，无报错**

探针素材按要求使用独立、无敏感信息的 HTML，放在**受控临时目录**且**不在任何 git 仓库内**：

```
路径：%TEMP%\issue6-probe\preview-probe.html
内容：<html><body><h1>preview probe</h1></body></html>   （48 字节）
```

调用原生 `present_files`（参数：`files` + `cwd` + `explanation`），结果：

- **工具是否可用**：可用，未被拒绝，**对 HTML 也不报错**。
- **调用参数**：常规三个参数即可，HTML **不需要任何特殊参数**。
- **错误**：无。
- **是否有卡片**：调用返回「已呈现 1 个文件……第一个会在预览面板中打开」——**产物卡片是产生的**。

**副作用实测（P4 的相关部分）**：

| 检查项 | 结果 |
|---|---|
| 登记后文件内容 | **逐字节未变**（SHA256 前后一致：`700D9FA0…4355`，48 字节） |
| 额外文件 | 无 |
| `.git` 生成 | 无（该目录不在任何仓库内，故未触发版本化） |

即：在**非仓库目录**中登记 HTML，**没有观察到内容改写或版本化副作用**。

### P2 — **判定为不成立（依据产品自身的工具契约）**

点击卡片后能否在 Desktop 内预览实际 HTML —— 这一条**未做 UI 目视确认**（无法由脚本观测渲染结果）。但**产品自身的工具契约对本版本是明确的**：

- 内联预览格式**仅** `mp4 / m4v / webm / mov / ogv`，**其余一律回退为「文件卡片」或交给系统应用**；
- 并且契约明确要求：**不要用 `present_files` 打开 HTML**，HTML 页面应改用**本地静态服务 + 可点击 URL**。

→ HTML **不在内联预览格式之列**，因此**不可能在侧边栏内嵌渲染**，点击后走的是「文件卡片 / 系统应用」路径。这与本 Issue 的现象描述一致（现有 `/usage-open` 本就把 HTML 交给系统浏览器）。

### P3 / P5 / P6 — 未执行（原因）

- **P3**：仅当 P1 失败时才需要，P1 已成功。
- **P5**：本项目 CLI 的 HTML 生成与打开路径**不依赖** `present_files`，因此禁用该工具不影响既有能力——这一点由设计即成立，无需实测。
- **P6**：前提是「内嵌预览可用」；P2 已判定不成立，该项**不再适用**。

### 结论：**No-Go**

| 判据 | 实际情况 | 命中 |
|---|---|---|
| 工具不能被应用调用 | 可以调用 | ✗ |
| **仅文件卡片 / 外部打开，而不能预览** | **HTML 不在内联格式之列，只能得到文件卡片或交给系统应用** | **✓** |
| 副作用无法接受 | 未观察到内容改写与版本化（非仓库目录） | ✗ |

**按判据「记录 No-Go，关闭当前预览路线」处理。**

### 判据纪律（务必遵守，防止误判）

- **不得**把「有产物卡片」误判为「支持侧边栏 HTML 预览」——P1 证明**卡片确实会产生**，但 P2 证明它**不能内嵌渲染 HTML**。两者是不同能力。
- **不得**为了通过测试而修改 Desktop 程序包；**不得**转向 `app.asar` patch。
- 本次实验**未修改 `app.asar`**、未注入桌面 UI、未使用真实用量数据或隐私路径。

### 遗留与后续

- 本条的「通过后才允许的实现」五项**不予启动**（No-Go）。
- 若未来版本的 `present_files` 契约把 HTML 纳入内联预览格式，可依据本文件的判据重跑 P1/P2。
- `/usage-open` 的既有行为（本地 loopback 只读服务 + 系统浏览器打开）**保持不变**；看板本身的会话绑定问题由独立的 Issue 跟踪，与本条无关。
