# MiMo Desktop Windows 实机部署与验收提示词

本项目的目标环境是 **MiMo Desktop Windows 客户端**。自动化测试负责验证可重复的代码行为；安装路径、真实配置、真实数据库、MiMo 命令表加载和用户界面效果，需要在用户自己的 Windows 电脑上由本地 MiMo AI 协助检查，再由用户亲自确认。

## 使用原则

- 先侦察、报告，再安装；不得猜测路径后直接覆盖配置。
- 不输出数据库中的对话内容、提示词、Token 或其他隐私数据。确认数据库是否存在、文件大小/更新时间和表结构即可。
- 修改 mimocode.jsonc 前创建带时间戳的备份；只改本项目相关的 command.usage、command.usage-open，保留其他命令、插件和用户配置。
- 不删除旧文件或配置，除非用户明确确认。
- 安装后由用户亲自重启 MiMo Desktop、开启新会话、执行命令并确认 HTML 看板内容。
- 任何失败都要记录完整错误信息、实际路径、命令和退出码；不得声称未执行的测试已通过。

## 提示词 1：只侦察本机安装与数据路径

将下面内容发给 MiMo Desktop 中具备本地终端/文件访问能力的 AI：

> 我正在验收 MiMo Usage Dashboard。请先只做只读侦察，不要安装、修改、删除或重启任何东西。
>
> 1. 确认当前运行的 MiMo Desktop Windows 客户端进程、可执行文件路径、版本信息（如果能安全读取），并区分安装目录与用户数据目录。
> 2. 搜索当前用户目录和 MiMo 配置目录，定位实际使用的 mimocode.jsonc、命令/插件配置目录，以及 MiMo 数据库 mimocode.db。优先检查已知目录和应用进程参数，再扩大搜索范围；不要全盘无边界扫描。
> 3. 对每个候选路径说明“已确认 / 推测 / 未找到”，给出证据。若找到多个配置文件，请说明哪个最可能被当前客户端加载，暂时不要修改。
> 4. 对数据库只确认存在性、大小、更新时间、SQLite 表名；不要输出消息正文、会话标题、Token 内容或其他用户数据。
> 5. 检查 Python 是否存在以及版本是否至少为 3.10；报告 python.exe 的完整路径。
> 6. 最后给我一份路径清单，并等待我确认后再进行安装。
>
> 请用 PowerShell 命令完成可重复的检查，避免猜测路径。不要把应用安装目录、配置目录、数据库目录混为一谈。

## 提示词 2：安装前检查与备份

> 请根据我确认的路径安装 MiMo Usage Dashboard。先确认项目源代码目录、usage_cli.py、register_command.py、实际生效的 mimocode.jsonc 和 Python 解释器路径。
>
> 安装前请：
>
> 1. 检查 Python 版本至少为 3.10。
> 2. 检查目标脚本与配置文件是否存在，确认目标配置确实属于当前 MiMo 用户。
> 3. 为 mimocode.jsonc 创建独立的带时间戳备份，并记录备份路径。
> 4. 展示将要复制/更新的文件与配置键；如果目标路径与我确认的路径不一致，先停下来询问。
>
> 得到我确认后，才将 usage_cli.py 和 register_command.py 安装到稳定的用户目录，并通过以下方式注册固定的 /usage 和 /usage-open 命令：
>
>     python register_command.py --config "<实际配置路径>" --python "<python.exe完整路径>" --script "<安装后的usage_cli.py路径>"
>
> 不要将 $ARGUMENTS 或其他用户输入拼接进 shell 命令。只修改本项目拥有的命令键，保留配置文件中的其他设置。不要删除旧文件或插件，除非先列出并取得我的明确同意。

## 提示词 3：安装后本地自动测试

> 请在 Windows 上执行本地自动化检查，不要使用我的真实用量数据库作为测试数据，也不要将任何用量数据上传到网络。
>
> 1. 在项目目录运行 python test/test_python.py。
> 2. 运行 node test/runtime-check.mjs。
> 3. 运行 node test/command-e2e.mjs。
> 4. 运行 npm test 和 npm pack --dry-run。
> 5. 对每个命令记录实际使用的解释器路径、退出码、PASS/FAIL 数量和失败摘要。
> 6. 确认端到端测试使用临时 SQLite 数据库，不依赖真实用户的 mimocode.db。
> 7. 如果有任何失败，保留错误日志并定位原因，不要通过跳过断言或伪报成功来让测试变绿。
>
> 完成后给我一份测试报告。自动化测试通过不代表 MiMo Desktop 中的命令已经加载；下一步必须由我在客户端亲自确认。

## 提示词 4：MiMo Desktop 客户端实机验收

> 自动测试完成后，请指导我在 MiMo Desktop Windows 客户端进行实机验证。不要代替我声称 UI 已经验证成功。
>
> 1. 先让我确认配置备份已经存在。
> 2. 提醒我彻底退出并重新启动 MiMo Desktop，然后新建一个会话（命令表可能在会话创建时加载）。
> 3. 让我输入 /usage，检查是否生成 HTML，并记录返回的绝对路径。
> 4. 让我打开 HTML，亲自确认三个标签页：总体使用量、会话使用量、上下文使用量；检查数据是否合理、标签能否切换、页面是否完整显示。
> 5. 再让我输入 /usage-open，确认默认浏览器是否打开新生成的看板。
> 6. 如有失败，收集命令原始输出、错误文本、配置文件路径、脚本路径和客户端版本。不要复制或发送数据库中的私人对话内容。
> 7. 最后请让我逐项确认：命令注册成功、重启后生效、/usage 成功、HTML 可打开、三个标签页正常、/usage-open 正常。未确认项应标为“未验证”，不要标为通过。
