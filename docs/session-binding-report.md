## 2. 引擎侧实证：斜杠命令能拿到什么

> 方法：只读抽取本机 `D:\Program Files\Xiaomi MiMo\resources\app.asar`（88 MB）中的 `out/main/node.mjs`（35.6 MB）检索。
> **`asar.extractFile` 对打过补丁的包会失败**，必须走 `getRawHeader` → 数据区起点 = `8 + headerSize` → 按条目 offset/size 切片。
> 下文偏移量均为该 bundle 内的字符位置，便于复核。

### 2.1 `command` 配置项支持哪些字段

| 字段 | 作用 |
|---|---|
| `description` | `/` 菜单里显示 |
| `agent` | 由哪个 agent 跑这条命令 |
| `model` | 指定模型（`provider/model` 或 group 名） |
| `subtask` | `true` 则当成子 agent 跑 |
| `template` | 正文/模板；其中的 `!` 反引号行会被本地执行 |

**三个注册来源，后者不覆盖前者**：① 配置 `command` 字段 → ② MCP prompts → ③ Skill。
因此注册 `command.usage` 即可接管同名技能——v0.2 正是靠这条接管 `/usage` 的。**命令热重载于下一轮对话生效**，无需重启应用。

另有一条**文件式**路径（引擎自带文档 @15675866 记载）：`.mimocode/command/<name>.md`（`.mimocode/commands/`、`.claude/command(s)/` 也读），frontmatter 配 `description/agent/model/subtask`，正文即模板。**但本机 bundle 里我按 `command/${`、`command/*.md`、`COMMAND_DIR` 检索均未找到加载器 glob**，其可用性未被证实（见 §2.6）。

### 2.2 模板流水线（六步）

```
用户输入 /usage-open 任意参数
 ① 取 cfg.command["usage-open"].template        ← 注册时写死的静态文本
 ② 替换 $1 $2 …（位置参数，末位吃掉剩余）
 ③ 替换 $ARGUMENTS（整串）
 ④ 模板无占位符且有参数 → 把参数追加到模板末尾
 ⑤ SHELL_REGEX = /!`([^`]+)`/ 扫描整段模板 → 本地 shell 执行 → stdout 插回原位
 ⑥ 整段替换后的模板作为 prompt 发给模型（模板里的中文指令要求模型只复述那一行）
```

源码依据：占位符定义与替换 @31193265；shell 执行 @31194463。

### 2.3 输入面：只有 `$ARGUMENTS` 与 `$1..$n`

引擎自带文档（@15675866）原文：

> Placeholders: `$ARGUMENTS` (all args), `$1`, `$2`, … (positional). If none are present, args are appended.

**两者都只是「用户在 `/` 后面键入的文本」**，没有任何会话信息字段。

### 2.4 `!` 命令的执行环境：不传 `cwd`、不传 `env`

```js
// @31194463 —— 模板 shell 执行
(await exports_process.text([cmd3], { shell: sh, nothrow: true })).text

// @2172515 —— 落到 spawn
const proc = import_cross_spawn.default(cmd[0], cmd.slice(1), {
  cwd: opts.cwd,                                            // ← undefined
  shell: opts.shell,
  env: opts.env === null ? {} : childProcessEnv(opts.env),   // ← 未传 env
  ...
```

`opts.cwd` 为 `undefined` → 子进程继承**引擎进程自己的工作目录**；`env` 未传 → 继承引擎进程环境。引擎是长驻进程，其 cwd/env 在启动时固定，**不可能携带「本次是哪个会话」**。

**对照**：模型调用的 *bash/shell 工具* 才有 `cwd: input.directory` / `cwd: input.worktree`——那是另一条路径，与斜杠命令模板无关。

### 2.5 实测：A–E 五会话得到同一个 URL

用真实代码路径（`usage_cli.main(["all","--open"])`，与已注册的 `/usage-open` 等价；仅把 `webbrowser.open` 换成捕获器以免真弹窗）：

```
合成库：A(50分钟前) B(40) C(30) D(20) E(10) → 最新活跃是 E
五次调用捕获 5 个 URL；去重后 1 个
唯一 URL = http://127.0.0.1:39315/eor61XNt…/?session=latest&days=30&kind=all
服务实例：复用同一个（同 port / 同 pid / 同 token）
五个标签页看到 → sessionId=E  mode=latest  title=会话E
让 A 再活动一次 → 五个标签页刷新后全部变成 sessionId=A
对照 --session B → sessionId=B  mode=fixed；之后让 E 变成最新，仍是 B
```

结论：默认路径下五个标签页**完全同源**，且**都跟着「此刻最新的会话」漂移**；固定模式必须显式传 `--session`，而斜杠命令不传。

- **探针已按用户要求删除**；实验未执行，结论未定。

### 2.7 一个必须记住的陷阱：`SHELL_REGEX` 扫描整个模板原文

`shell()` 对**整段模板原文**做正则，**不排除代码块与行内代码**（`docs/architecture.md:101` 已警告）。因此模板正文里**不能出现任何示例性的「叹号 + 反引号」**，否则那段散文会被当成真命令执行。

本次已实际踩到：第一版探针正文里写了「叹号 + 反引号」作示例，自检扫出的 shell 行是**散文**而不是预期命令。**任何新模板都必须自检**：反引号总数 = 2、扫出的 shell 行数 = 1、且内容等于预期命令。

## 4. 路线评估

要让「A 的页显示 A」，必须把会话身份送进这条链路。四条可选路线：

| 路线 | 做法 | 需要桌面配合 | 安全影响 | 主要代价 |
|---|---|---|---|---|
| **A** | 模板改成带 `--arg-string "$ARGUMENTS"`，**让用户自己键入会话 id** | 否 | **重新打开 shell 插值面** | 见 §4.1 |
| **B** | 用插件 hook 注入会话（`shell.env` / `command.execute.before`，或插件工具的 `ctx.sessionID`） | 需插件 | 中性 | 与 v0.2「零 AI 参与」定位冲突；要重新引入整套插件机制 |
| **C** | 把绑定挪进页面（看板页加「钉住会话」控件，用 `history.replaceState` 写 `?session=`） | 否 | 无 | 「打开后再钉」，不是「一开就对」 |
| **D** | 脚本用 `!` 命令的工作目录去 `session` 表按 `directory` 反查会话 id | 否 | 无 | **前置条件未证实**（§2.6） |

### 4.1 路线 A 为什么需要重新论证，而不能顺手做

- 引擎**先**做 `$ARGUMENTS` 文本替换、**再**扫 shell（§2.2 步骤 ②③ 在 ⑤ 之前）。因此模板里的引号**不是可靠的转义层**：含单引号的输入可能提前结束 PowerShell 单引号字符串，在 Python 启动前执行额外 shell 语句。这正是 v0.1.x 被判不安全、改成固定命令的原因（`docs/architecture.md` §5）。
- 现有多处断言会与路线 A 直接冲突，必须一并重新论证而非改绿：
  - `test/command-e2e.mjs:82`、`:127`（模板不得含 `$ARGUMENTS` / `--arg-string`）
  - `test/test_python.py:746`、`:806`
  - `test/install-smoke.ps1:71`
- 附带体验问题：用户在会话里手打会话 id 很别扭，而 UI 只显示短 id 前 12 位。

### 4.2 路线 B 的真实吸引力与真实代价

路线 B 是**唯一能免费拿到会话 id** 的通道：插件工具的 `execute(args, ctx)` 里 `ctx.sessionID` 就是发起会话的 id（类型定义见 `@mimo-ai/plugin/dist/tool.d.ts`）。但：

- v0.2 已经为「零 AI 参与」把插件机制拿掉（`skill/` 于 2026-10-14 删除、CLI 与 CI 均无引用）。走 B 等于把这条机制请回来一部分。
- 插件**没有 UI 注册能力**（`PluginModule = { server, tui?: never }`），所以 B 只能解决「会话身份」，解决不了产物预览。

### 4.3 路线 C 与 D 的关系

C 与 D 都不需要桌面配合、都不引入安全让步，**可叠加**：D 解决「一开就对」，C 作为 D 不可用时的兜底与用户可覆盖手段。§5 的提案是在 C 的基础上补一个自动动作，把「需要用户手动钉」变成「自动定格，但可一键回到最近活跃」。

## 5. 新提案：唯一 URL + 首次打开定格

### 5.1 问题精确化

「每次请求生成一个新网址」**本身不足以**解决问题——URL 唯一只说明它们是不同的标签页，不说明每个页该显示哪个会话。差别在这一张表里：

| 时序 | ① 现状（相同 URL，每次重解析） | ② 只加唯一 URL | ③ 唯一 URL + 首次打开定格 |
|---|---|---|---|
| A 打开看板 | `?session=latest` → 显示 A | URL₁ → 显示 A | URL₁ → 解析为 A，把 `?session=A` 写回地址栏 |
| B 打开看板 | **同一个 URL** → 显示 B | URL₂ → 显示 B（独立标签页） | URL₂ → 解析为 B，写入 `?session=B` |
| A 刷新 | 重新解析 → **变成 B** ✗ | URL₁ 里还是 `latest` → **仍变成 B** ✗ | `?session=A` → **仍是 A** ✓ |

关键差别不是「URL 唯一」，而是**「打开后把当次解析结果固化进自己的 URL」——一次解析，之后不再重解析**。

### 5.2 机制（很轻，且不需要任何桌面配合）

页面首次加载时，载荷里**本来就有**当次解析出的真实会话 id（`context.sessionId`，界面当前也已显示它）。因此页面只需：

1. 首次渲染后，用 `history.replaceState` 把 `?session=<该 id>` 写回自己的地址栏；
2. 让「刷新数据」改用这个带 id 的 `reportUrl`（前端改写 `LIVE.reportUrl` 即可，服务端不必改）。

两处都是纯客户端行为：**不需要改斜杠命令、不碰 shell 模板、不新增服务端接口、不引入 shell 注入面**。

### 5.3 唯一 URL 仍然值得加，但目的是另一个

现状下五次 `/usage-open` 得到的 URL 完全相同，浏览器很可能**只是聚焦已有标签页**而不是新开，导致无法并排查看两个会话。给每次调用加一个 nonce（或等价物）即可让每次调用真正独立成一个标签页。这与 5.2 是两件互补的事。

### 5.4 必须写清的残余缺口

这套机制给出的是「**打开那一刻的最近活跃会话**，且之后不再漂移」，**不等于**「A 的页显示 A」：

- 若 B 在 A 打开看板**之前**刚活动过，A 的标签页会定格在 B 上——只是它会**明确标注**「已定格：会话B · B」，而不是无提示换人。
- 要真正做到「A 的页显示 A」，仍需路线 D（前置条件未证实）或路线 B。

**因此本提案的定位应表述为「消除同一页面悄悄换人」，而不是「实现会话绑定」。** 不要把它写成后者。

### 5.5 建议的界面与验收标准

界面：卡片上显示「已定格：<会话标题> · <短 id>」，并提供一个「回到最近活跃」的开关（让两种模式都可达、且状态可见，符合本项目「可核对」的风格）。

验收标准（建议）：

- A 打开看板 → B 触发 `/usage-open` → A 刷新：**A 仍显示 A**（定格生效），且卡上标注被定格的是谁。
- 地址栏在定格后可见 `?session=<id>`；直接复制该 URL 到新标签页打开，显示同一会话。
- 点「回到最近活跃」后恢复跟随最新活跃会话，且有明确标注。
- 每次 `/usage-open` 产生的 URL 互不相同，可同时并存两个会话的标签页。
- 不改变 loopback 服务的安全边界（path token、Host/Origin 校验、`pointer-events` 无关项等保持原样）。
- 静态快照（`/usage` 与 `usage_cli.py` 直接调用）行为不变。

非目标：不引入 `$ARGUMENTS` / `--arg-string`；不引入插件；不做 app.asar 补丁。

## 6. 产物预览（Issue #6）评估

- 文档结论栏现状：实机验证**未执行**，决策**待验证**。

### 6.2 本轮补充的证据（指向 Go 条件可能不成立）

在本次会话中**原生 `present_files` 工具是可用且文档化的**，其契约明确写着：

- HTML **不在**内联预览格式之列——内联只支持 `mp4 / m4v / webm / mov / ogv`，其它「回退为**文件卡片**或交给系统应用」；
- 并且明确指示「**不要**用 `present_files` 打开 HTML 文件，应改用本地静态服务」。

据此预判：

| 项 | 预判 | 理由 |
|---|---|---|
| P1 | **成功**（会出现产物卡片） | 登记任意文件是原生能力 |
| P2 | **很可能失败**（不能在 Desktop 内渲染 HTML，回退到系统浏览器） | HTML 非内联格式 |
| P6 | **很可能不成立** | 内嵌预览不允许动态连接；`sci-widget` 的 CSP 是 `connect-src 'none'` |

按 spike 自己写的 Go/No-Go，该结果落在 **No-Go**。

### 6.3 建议

1. **只跑 P1 / P2 两项实测**（用无敏感信息的测试 HTML，成本极低）确认上述预判，**不要再投入实现**。
2. 若 P2 确实失败，按 spike 的 No-Go 分支收尾，把 Issue #6 的结论写成「当前应用版本不支持侧边栏内嵌预览」，并保留「产物卡片」这一部分可做的收益。
3. **无论结果如何都要注意定位取舍**：让 agent 调用 `present_files` 等于把 AI 重新拉进这条链路，而 v0.2 的定位是「零 AI 参与、模型只复述一行」。登记产物需要模型额外调一次工具——这是一处定位取舍，应与产物预览一起决策，而不是顺手加上。
4. 实时看板在**对话内或侧边栏**都做不到页内刷新（需要 `127.0.0.1` 连接），这一点在 v0.2 架构文档 §4.3 已记录；产物预览只能改善「能打开」，不能改变「实时刷新必须靠真实浏览器 + loopback 服务」。

### N1 —— `/usage-open` 打开的看板会随「最近活跃会话」漂移

**标题**：`/usage-open` 打开的看板会随「最近活跃会话」漂移：同一标签页刷新后可能换人（建议：唯一 URL + 首次打开定格）

**背景与证据**：

- 斜杠命令模板是静态文本、不传 `--session`，因此每次调用都得到同一个 `?session=latest&days=30&kind=all`（引擎侧原因见 `docs/session-binding-report.md` §2）。
- 实测：A–E 五个会话各触发一次 `/usage-open`，**5 次调用去重后只有 1 个 URL**，复用同一服务实例，五个标签页都显示「此刻最新活跃的会话」；让 A 再活动一次后，五个标签页刷新后**全部变成 A**。
- 后果：用户在 A 打开的看板，会在他不知情时换成别的会话的数字。Issue #4 已把它从「无提示」改善为「有标注」（卡片标题 + 「会话：<标题> · <短 id>」），但**漂移本身仍在**。

**期望行为**：每个 `/usage-open` 打开一个独立标签页，并在首次解析后把会话固化下来，之后刷新不再漂移。

**验收标准**：

- A 打开看板 → B 触发 `/usage-open` → A 刷新：**A 仍显示 A**，且卡上标注被定格的是谁。
- 定格后地址栏可见 `?session=<id>`；复制该 URL 到新标签页打开显示同一会话。
- 提供「回到最近活跃」开关，切换后状态可见。
- 每次 `/usage-open` 产生的 URL 互不相同，可并存两个会话的标签页。
- 不改变 loopback 安全边界；静态快照行为不变。

**范围 / 非目标**：不引入 `$ARGUMENTS` / `--arg-string`；不引入插件；不做 app.asar 补丁。

**风险与备注**：本方案定位是「消除同一页面悄悄换人」，**不是**「实现会话绑定」——若 B 在 A 打开之前刚活动过，A 的页仍会定格在 B（只是标注清楚）。真正的会话绑定依赖 N2 或插件方案。与 Issue #4 的关系：Issue #4 验收标准 1 已满足，本条是独立改进；也可选择把 Issue #4 的验收标准 1 扩写以覆盖它。

### N2 —— 探针实验：`!` 命令的工作目录是否等于会话目录

**标题**：探针实验：确认斜杠命令本地执行沙箱的工作目录/环境是否携带会话身份（决定「按目录反查会话」是否可行）

**期望行为**：给出明确结论——`!` 命令能否看到会话级信息。

### N3 —— 防御性：实时服务的原始 query 未转义回显进 `<script>`

**标题**：实时看板把请求的原始 query 未转义回显进页内 `<script>`：`?session=</script>` 可提前闭合脚本元素

**背景与证据**（PR #10 引入）：

- 首页处理器把**原始 query**（`self.path.partition("?")[2]`）拼进 `live["pageUrl"]` / `["reportUrl"]`，`render_html` 再用 `json.dumps` 把它嵌进 `<script>` 里的 `var LIVE = {...}`；而 `json.dumps` **不转义 `<` `>` `/`**。
- 实测（合成库 + 临时 loopback 服务 + 裸 socket 发送原始字符）：
  `GET /{token}/?session=</script>` → **200**，响应体 `var LIVE` 内出现**未转义**的 `</script>`。
- `_request_options()` 对 `session` 的校验只禁控制字符与超长，**放行了 `</script>`**。

**严重度评估（诚实版）**：**防御性缺口，不是可直接利用的 XSS**——浏览器通常会把 `<` `>` 百分号编码，服务仅监听 loopback，URL 又带 16+ 字符随机 path token。但它与本项目既有的安全姿态（`ping` 的精确集合断言、Host/Origin 校验、处处 `esc()`）不符。

**期望行为**：回显进页面的内容要么是**已校验参数重新编码**的结果，要么经过转义。

**验收标准**：

- 响应体中不出现未转义的 `</script>` 序列。
- 非法 `session`（含 `<`/`>`/引号/空白外字符集）被拒绝或安全转义；正常会话 id 与 `latest` 行为不变。
- 现有断言（ping 精确集合、Host/Origin、path token）保持通过。

**建议修法**（任选其一）：回显时用**已校验参数重新 `urlencode`**（顺带归一化）；或把 `session` 校验收紧为字符集白名单（真实会话 id 形如 `s1`，`[A-Za-z0-9_-]` 足够）。

**范围 / 非目标**：不改实时刷新的功能语义。
