## 6. 刷新机制评估

### 6.1 用户点击刷新后，数据是否会重新从 SQLite 读取？

**否。** — **已证实（浏览器直接证据）**

### 6.2 直接证据（E11）

CDP 实测点击 `#regen`：
- `window.fetch` 调用次数 = **0**
- `XMLHttpRequest.open` 调用 = **0**
- `tab-content` innerHTML 长度 **不变**（未重算）
- 行为：`alert` + `navigator.clipboard.writeText(CMD)`
- alert 原文：「数据是静态快照，无法在页面内刷新。请重新运行这条命令：…」

源码：`usage_cli.py:964-972`（仅 alert/clipboard），`README.md:140-142`（自述静态快照）。

### 6.3 现有刷新按钮究竟做了什么？

1. 把 `build_command_hint(...)` 生成的命令串写入剪贴板（若有 clipboard API）。
2. `alert` 提示用户手动重跑该命令。
3. **不**重读 DB、**不**重算指标、**不**重写 HTML 文件。

注意区分：
- 页面重绘（Tab 切换）= 仅 `renderTab` 重写内联 `DATA` 的 DOM → **不是数据刷新**
- 浏览器 F5 重载 HTML = 仍读取**生成时内嵌**的同一 `DATA` → **不是数据刷新**
- 真正刷新 = **重新执行 CLI**，从 SQLite 重新聚合并写出**新的** HTML 文件

### 6.4 真正实现刷新还缺少什么？

静态 `file://` HTML 无法：
- 安全读取 `~/.local/share/mimocode/mimocode.db`
- 无本地代理时跨源请求任意路径
- 自己 spawn `python usage_cli.py`

可选路径：

| 方案 | 机制 | 优点 | 缺点 |
|---|---|---|---|
| **A. 维持「重跑命令」**（现状） | 用户再跑 `/usage` | 零服务、零端口、安全 | 无一键刷新 |
| B. CLI `--open` + 文件监视/覆盖同文件 | 重跑覆盖同路径 | 流程短 | 仍需外部触发 |
| C. 本地极小 HTTP/WS + 只读 API | 页面按钮请求 `/api/usage` | 真一键刷新 | 违背「零服务」设计；攻击面扩大 |
| D. MiMo 命令按钮/侧栏动作再执行 `/usage` | 由宿主触发 | 贴合宿主 | 依赖 MiMo 能力，**未验证** |
| E. `file://` + File System Access / Native Messaging | 浏览器扩展 | 可自动 | 兼容性差、安装成本高 |

**推荐：** 短期保持 **A**（与产品「零 AI、零服务」定位一致），在 UI 上把按钮文案改为「复制重跑命令」以免误导。
若产品明确要一键刷新，优先 **D**（宿主命令），其次 **B**（同路径覆盖 + 浏览器手动 F5），避免 C 破坏安全模型。

## 8. 问题清单

> 去重：根因优先；症状归并。

### BUG-001 · P1 · Windows `--db` 反斜杠路径被静默丢弃并回退默认库

- **文件/行号：** `usage_cli.py:1033-1065`（尤其 L1046 禁 `\`；L1058 对非 `--out` 含 `\` 整对丢弃；L1055 仅 `--out` 例外）
- **复现：**
  ```
  python usage_cli.py --db C:\Users\x\custom.db --out C:\tmp\out.html
  ```
- **实际：** sanitize 输出 `[]` 或仅剩 `--out`；`main` 使用 `default_db_path()`（本机该文件存在）→ exit 0、「已生成」
- **预期：** 使用指定库，或明确报错；禁止静默换库
- **证据：** `_probe_sanitize.py`（IN `['--db','C:\\path\\...']` → OUT `[]`；backslash 分支 exit=0）
- **稳定复现：** 是（纯逻辑）
- **影响：** Windows 用户/脚本指定测试库时读到**真实隐私库**并生成错误报告；自动化误判
- **根因：** 把 `\` 当 shell 元字符一票否决，且 `--out` 有豁免、`--db` 没有
- **修复建议：**
  1. 路径型选项（`--db/--out/--session`）统一规范化：接受 `\` 与 `/`，仅拒绝真正的 shell 元字符 `;|&$\`><\n\r`
  2. 或在入口 `os.path.normpath` 后再校验
  3. **禁止**丢弃参数后回退默认库；应显式 error
- **可直接修复？** 可以（局部逻辑），但改安全白名单建议回归注入用例后再合

### BUG-002 · P2 · `command-e2e.mjs` CWD 依赖 + 硬编码 Python
