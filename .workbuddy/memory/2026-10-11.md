### 关键 Bug 修复：$ARGUMENTS 引号包裹（重要）

`command` 模板里 `$ARGUMENTS` 的包裹方式**直接决定安全性与可用性**。

| 写法 | 输入 `token ; echo x` | 输入 `--out "C:\a b\x.html"` |
|---|---|---|
| 裸接 | ❌ PowerShell 语法错，整行失败 | ✅ |
| 双引号 | ✅ 挡住 | ❌ 内层引号提前闭合，`--out` 被静默丢弃 |
| **单引号** | ✅ 字面文本 | ✅ 内部双引号保留 |

最终采用 **`--arg-string '$ARGUMENTS'`**（PowerShell 单引号 = 字面串）。

配套改动：
- `usage_cli.py`：`_split_args()` 改为**自写引号拆分器**，不用 `shlex`
  （`posix=True` 会吃掉 Windows 路径的 `\`：`C:\Users\a` → `C:Usersa`；
   `posix=False` 又不处理嵌套引号）
- `usage_cli.py`：`--arg-string` 之后**所有** argv 元素拼回整串再解析
  （裸接单引号后 shell 会按空白拆成多个元素，只取一个会丢后半段）

### 已知限制

PowerShell 传参给外部程序时会剥掉内层双引号 → 含空格路径的 `--out` 会散架。
实际不受影响：用户一般不传 `--out`（走默认当前目录），且默认路径无空格。

## 第二轮：修复热力图丢失 + 缓存命中率渲染错误

### 1. 热力图丢失

**原因**：v0.2 重写 `tokenCard` 时，旧版 `dashboard.html` 里的 `heatmap()` 函数
没有被移植，渲染层直接漏掉了。

**修复**：新增 `heatmapCard(t)`，恢复 12 个月 × 每日 tokens 的 GitHub 风格日历热力图。
- 4 档分位配色（只对 `>0` 的值取分位，避免大量 0 拉低阈值）
- `grid-template-columns:repeat(nc,minmax(0,1fr))` 让格子铺满卡片宽度
- `aspect-ratio:1/1` 保证格子是正方形（先前用 `height:var(--cell)` + `width:100%` 会变扁矩形）
- 月份标签用 `grid-column: N / span 3` 精确定位（原来每列放一个 `<div>`，文字宽度撑破单列导致错位）

**数据层配套**：`card_data` 原来把 `daily` 按 `--days` 过滤了（默认 30 天），
热力图需要全年。现拆成两个字段：
- `token.daily` — 全量，供热力图（**不受 `--days` 影响**）
- `token.recent` — 范围内，供 Hero 卡的迷你趋势

### 2. 缓存命中率「图层问题」

不是图层，是**配色语义错误**：

```css
/* 错误做法 */
.seg-fresh{background:var(--accent)}
.seg-cache{background:var(--accent);opacity:.35}
```

两个类用**同一个颜色**，只靠 `opacity:.35` 区分 —— 叠在白色卡片上淡到几乎不可见。
而且「模型份额」那条 `.track2` 进度条是**单一实心色块**，只表示份额占比，
**根本没有缓存命中的分层**，图例写着「未命中/命中」纯属**虚假图例**。

**修复**：
- 改用**实色**：命中 `#8fb0fb`（浅蓝）／未命中 `#f59e0b`（橙，警示）
- 模型行现在有**两条独立 bar**：`.track2` 份额条（单色，锚定最高模型）
  与 `.track3` 命中率条（分层），不再混用语义
- 命中率普遍 >97%，未命中段仅 2–3% 几乎不可见 → 用 `Math.max(pct, 1.6)`
  强制最小可见宽度

### 3. 配色语义隔离（后续发现）

`contextCard` 复用了 `seg-cache`/`seg-fresh`，但那里的语义是
「缓存读取 / 新输入 / 推理 / 输出」—— 把「推理」「输出」标成橙色（警示色）语义错误。

**修复**：拆成两套类名，语义不再重叠
- 模型行命中率条：`cm-hit-hit` / `cm-hit-miss`
- 上下文构成条：`ctx-cache` / `ctx-input` / `ctx-reason` / `ctx-output`（四色）

### 4. 区块顺序

按用户要求调整为：**Hero → 8 个统计小卡(2×4) → 热力图 → 按模型的调用情况**。
8 小卡为：输入 / 输出 / 缓存读取 / 缓存命中率 / 请求数 / 工具调用 / 会话数 / 平均每次请求。

### 5. 数据层补字段

模型维度原本缺 `requests`/`tools`（工具调用只记到会话维度）。新增：
- `session_model: {session_id: model_key}` 映射
- 模型累计 `dailyReq` / `dailyTools`
- `card_data` 按 `from_date` 汇总这些字段

### 6. 响应式

- 新增 `.tw` 包裹会话表格 → 窄屏横向滚动，不再挤扁
- 热力图 `--minw` 最小宽度 → 窄屏横向滚动而非压成细条
- `@media(max-width:720px)` 加大 `.page` / Hero 大号的降级

## 第三轮：修两个真实渲染 bug（用户截图反馈）

用户反馈「新的渲染图也不太对」。放大裁剪截图逐区检查，发现两个 bug：

### 1. 热力图图例色块不可见（「少 [空白] 多」）

**根因**：图例 `<div class="legend">` 在 HTML 里位于 `.hm` 容器**之外**，
而色块尺寸规则写的是 `.hm .legend i{width:11px;...}` —— 选择器匹配不上。
`<i>` 是行内元素、无内在尺寸 → 五个色块宽度为 0，只剩「少」「多」两个文字。

**修复**：色块改为**内联样式**直接写
`display:inline-block;width:11px;height:11px;border-radius:3px;background:…`，
不再依赖后代选择器。

### 2. 「缓存读取 0」—— JS/Python 字段名不一致

截图里 8 小卡显示「缓存读取 0」，但实际缓存读取 831M。

**根因**：Python `card_data` 的 totals 写 `"cacheRead": sum_["read"]`，
JS `tokenCard` 却取 `tot.read` → `undefined` → `fmt()` 返回 0。

连带发现语义问题：`totals.input` 存的是 `input+read` 合值（851.3M），
「输入 tokens」标签下显示合值有歧义。

**修复**：
- Python：totals 改存**原始值** `input`/`output`（不再预混合缓存），
  `cacheRead` 单列并加注释
- JS：8 小卡改为 `['输入', fmt(tot.input)]`、`['缓存读取', fmt(tot.cacheRead)]`、
  `['输出', fmt(output+reasoning)]`

**教训**：Python dict 字段与 JS 取值之间没有 schema 约束，
字段改名必须两侧 grep 同步；「显示 0」不一定是数据为 0，
可能是 `undefined` 被 `fmt()` 兜底。

### 3. 防回归：新增 test/runtime-check.mjs

把临时语法检查固化为第 4 套测试：用 `node:vm` 真正执行 `_RUNTIME` 的 JS，
调用 `buildBody()` 三种输入（all / token / 空数据），
